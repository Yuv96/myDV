# a5.4：返回播放页、直播列表与视频资料卡

最低 Android 5.0/API 21；保留 a5.3 的异步 native stop、选择世代、缓存容量/速度限制及软件 H.264 解码。

## 本轮修改

- 返回播放页时检查 LibVLC `areViewsAttached()`，在 SurfaceView 被销毁后重新 `setVideoView/attachViews`；保留原播放器和进度，不等待循环，不主动从头加载。原因是 LibVLC AWindow 在 surfaceDestroyed 时会解除绑定。
- 每个新视频重置尺寸，按可见尺寸、SAR 和编码 padding 计算等比居中区域，清除过期 aspect/scale 设置。
- 关注直播列表增加封面，缺少封面时用主播头像；列表复用行，缩略图两线程、2 MiB LRU、有限队列/下载/解码尺寸，无 Cookie 发送至图片 CDN。
- 播放资料卡整体采用一个带圆角的半透明渐变背景。昵称与点赞/评论/收藏/画质同一行，简介在下方。API 21 SurfaceView 不做实时背景模糊截图，以保留播放性能；这是半透明磨砂风格而非真实实时高斯模糊。
- 通知角标改为播放页前台独立每 30 秒查询，返回页面立即刷新，后台停止调度，使用独立工作线程，读取失败保留上次已知数值。**仍是抖音通知未读数，并非私信未读总数**；当前私信总数接口验证未成功。
- 分享打开可分页的好友列表，选中好友后只发送当前视频卡片（message_type 8 / aweType 800），没有文字输入框。只在选中好友之后建立单聊/提交视频；不自动重试发送；只有服务器返回成功和消息 ID 才报告提交成功。
- 用只读 `webcast/im/fetch` protobuf 拉取替换旧 chat/list JSON 接口，解析聊天消息、去重并走现有弹幕视图；失败退避、离开直播/账号变化丢弃过期结果。**验证时连续轮询没有收到聊天消息，真实直播弹幕展示仍待验证；不支持发送直播弹幕。**

## 验证边界

本地编译检查；GitHub Actions 在 API 21 上保留原 H.264、缓存、512 MiB/正文停滞、32 次往返等回归，并新增竖屏视频居中、真实 MainActivity 被不透明 Activity 覆盖后连续三次返回（画面输出/进度/播放器世代保持）、资料卡结构、好友分页/视频卡片与 protobuf 异常解析验证。

授权 Cookie 只用于本地只读接口核实，不进入仓库、APK、CI 或日志：个人登录、关注直播封面和好友列表已读通。**没有向真实好友发送测试视频；发送与审核结果需要在电视上实际使用验证。私信计数和真实直播弹幕尚不能宣称完成。** 合成模拟器测试不能代替具体电视机型验证。

## 协议资料

Java 代码为本项目实现；仅参考公共协议字段和请求形状：

- https://github.com/zhinjs/douyin-im （好友列表、IM envelope/会话/视频卡片字段）
- https://github.com/opedium/douyin-live-proto （WebcastChatMessage 字段）
- LibVLC 3.7.6 官方绑定源码的 AWindow / VideoHelper（随 Release 提供）

这些私有接口可能随抖音更新变化。失败状态与真实空列表分开处理，发送超时不等于未送达，请先在抖音中检查后再重试。
