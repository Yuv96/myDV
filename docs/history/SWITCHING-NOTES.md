# a5.3：慢网络与快速往返切换修复

最低 Android 5.0 / API 21，沿用 a5.2 的软件 H.264 解码和互动菜单。

## 修复范围

切换时，界面线程只解绑旧画面，耗时的原生停止放到后台。旧播放器停止、释放后才打开最新选中的视频，100 ms 内连续选择合并；始终最多一个播放器处于播放或退出阶段，避免不断创建解码器、线程和缓冲区。旧播放器事件及视频尺寸回调按代次丢弃。LibVLC 直接读取原始 CDN 地址，绕开旧本地代理每次切换后可能继续占用 60 秒的无界下载线程池；保留相同 User-Agent、Referer 和解码设置。

切换后显示明确的加载提示，底栏在视频输出建立后才显示；上/下键在加载期间仍可切换。加载超过约 20–22 秒，显示可恢复的错误，允许上/下切换或确定键刷新地址重试。移除原来未绑定选择的延迟刷新/自动跳过，防止返回上一条后被旧请求抢回。详情请求、头像及直播异步结果按选择代次校验。

下一条预缓存仍只接受完整 MP4，单条 32 MiB、总计 64 MiB，已知超大或未知长度直接跳过。后台下载增加 20 秒正文期限、3 秒读取超时、剩余空间检查及严格 512 KiB/s 限速。队列仅保留最新任务，重复缓冲事件不再反复创建取消线程；当前播放缓冲后至少等待 5 秒再预取。长视频正常选择后仍可在线播放，不会强制整条下载完才播放。

## 自动回归

除原有 H.264 High/Baseline、进度、预缓存命中、暂停、seek、倍速与菜单回归外，`SwitchingSelfTestActivity` 启动真实 MainActivity，用本机生成视频服务模拟 512 MiB 响应和正文停滞：32 次上下往返、回到上一条并恢复视频输出、过期头像回调拒绝、加载/底栏一致性、超时后的上一条恢复、主线程心跳、原生堆增长与缓存上限。

测试不读取个人 Cookie，不操作真实账号。模拟器回归不等同于已在用户电视复现所有崩溃；真实 CDN、设备内存和网络情况仍可能影响首帧等待时间。
